The state is one GitHub issue from a game project: its title, its body, and its labels.

Answer yes if what the issue describes is wrong in what the next release ships and a player
reaches in play, changing what the game does: an order that moves money, units or game state
where the original's rules would not move it (or moves it wrongly); a control, panel or screen
that is broken, absent, or wired to the wrong thing; a saved game that will not load or is
written wrong; something wrong in the release package itself.

Answer no for everything else, however wrong: presentation and wording (number formatting,
message phrasing, colours, titles, sounds), missing polish, shortcuts or help pages, a stale
comment, annotation or document, a tooling or test gap, a refactor.

The confusing case, both sides seen in the labels: a missing refusal. One that lets a wrong
transaction through — the order succeeds and money, supply or units end up where the original's
rules would not put them — is yes. One that only makes the game more permissive, the order
otherwise doing what was asked of it, is no. When a case stays confusing, it falls on the no
side: a release held for something a player cannot feel costs more than a polish issue shipped.
