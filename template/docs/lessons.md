# Lessons

Every rule in `CLAUDE.md` and `docs/process.md` is here with the failure that produced it. A rule
without a lesson does not belong in either file (L14). Append this project's own lessons from L100;
never renumber. The sources are
[imperial_conquest_2](https://github.com/diegoami/imperial_conquest_2) (IC2: its wiki's *Process
incidents*, its PRs, and the audit `docs/workflow-audit-2026-09.md`) and the field reports in
[harness_template](https://github.com/diegoami/harness_template).

| # | Rule | What happened |
| --- | --- | --- |
| L1 | A walking skeleton to a screen before the fan-out; until the first playable build, only bugs that break play are scheduled | IC2 merged 81 task PRs, 41 of them corrections, before its first real UI task, although a review ten days earlier had named the UI as the largest untested risk. The day the gate was adopted (#465), the UI tasks merged and v0.4.0 was tagged. |
| L2 | Status lives in labels, never in a document | IC2 incident 10: prose status synced after every merge kept drifting ("Docs: status resync" five times in one day). |
| L3 | The reviewer is another model family and re-runs every Done-when line | In IC2 a same-model reviewer twice repeated the implementer's misreading of the same claim. Reviewers filed 64 of 112 bugs; 82% of tasks went through at least one rework round. #482 enforces the family rule in the script. |
| L4 | A bug that changes no outcome is a `fix`, with one review round | IC2 incident 12: about half its correction tasks fit in one or two files but carried the full task ceremony; a review had proposed the lighter lane ten days before it was adopted (#471). |
| L5 | Owns names directories or files, not functions | IC2's line-level Owns lists produced 27 PRs that only widened an Owns list. |
| L6 | The main session edits task files on `main`, with the reason in the commit | IC2 opened 127 plan PRs against 84 task PRs. Their median time to merge was 6 minutes: the cost was attention and tokens, not waiting. |
| L7 | The implementer never weakens a Done-when; it stops and reports | IC2 incident 4: an implementer wrote outside its scope, wrote a reflection test that found nothing and could never fail, and documented a feature that does not exist. #482's trial implementer stopped correctly on a gap. |
| L8 | Review with an explicit target, and prove the tree first | IC2 incident 5: a review skill invoked bare from an agent ran in the main checkout and reviewed the last merge: four wasted passes and nine confident findings about the wrong commit. |
| L9 | A new test fails first; a "nothing failed" result is re-taken; mutations are tested after a clean rebuild; a tool that exits 0 on failure is judged by its log | IC2 incident 9: a stale binary gave phantom greens. boar_life's Godot exits 0 after a script error; IC2 #477 had the same false green. |
| L10 | OpenCode runs with stdin closed, a startup timeout, an idle timeout and a total deadline | IC2 #490: two runs hung before creating a session because stdin was a pipe that never closed. #482 measured that a session's `updated` time moves only between steps, which sets the idle limits (900 s implementer, 600 s review). |
| L11 | Whether OpenCode loaded the agent is read from its session record, never from the output | IC2 #480: a missing agent file makes OpenCode fall back silently to a full-permission agent. #482: a text check failed both of its own reviews, because the reviewers quoted the warning. |
| L12 | The next model runs only on an infrastructure failure that left no work; the same failure twice stops the chain | IC2 #482: a failed run can leave commits or a PR, and retrying on top of them loses work; two identical failures mean OpenCode is the problem, not the model. |
| L13 | Record tokens, models and rounds per task | IC2 never measured cost per task: #264's figures are file sizes. Baseline to beat: 82% of tasks reworked at least once, about 40% twice (Claude implementers). |
| L14 | A rule enters only with a lesson | IC2's process grew layers that each patched a failure the layer below created; harness_template's review records reached twice the size of the harness. |
| L15 | [rebuild] One fixtures corpus with provenance | IC2 incident 1: wrong constants merged quickly, and reviewers and research caught them, not implementers. |
| L16 | [rebuild] Evidence in two stages, four routes; research never decides design | IC2's evidence pipeline: later evidence produced 20 tasks for rules the plan did not have. |
| L17 | [rebuild] CI fetches the whole corpus from a private repository; tests find fixtures by name | IC2 #207: a named subset silently lost coverage for tests that read by directory. |
| L18 | A brief carries the task file, not a pointer | IC2 incident 14: a pointer cost about 85,000 tokens per agent per round to reach about 1,450 of contract. |
| L19 | Never `git stash` | IC2 #283: the stash is shared by every worktree of a repository. |
| L20 | An edge comment arrives with its test | IC2 incident 8: five false comments shipped, three about edges no test visited. |
| L21 | A question is not a request to edit files | pgn-postmortem's field report: the owner wanted a harness because the agent was "too eager to create stuff before we have fully planned it". |
| L22 | [entity graphs] Every delete asks: what still references it, are its resources conserved, does a cap still hold? | IC2 incident 7: removed entities left dangling ids, so the game wrote saves it could not reload. |
| L23 | Hunt the branch no input reaches | IC2 incident 6: a victory condition shipped that the game could never reach. |
| L24 | Repeated decisions with known answers go to Jev, trialled first, confident ends only | newscollection2027 #85 and #87: the Claude judge could not keep up with about 90 pairs a day. On held-out labels Jev's answers at 0.9 or above were 96–100% right; on the live queue the judge agreed with Jev's confident answers on 70 of 71 pairs. Jev took the ends and the judge the middle. |
| L25 | Model ids come from the provider's live list, never memory; every choice is recorded where it is used | IC2 #482 changed its implementer default three times in one day: the plan named models that `opencode models` on the machine did not list, and ids moved between versions. |
| L26 | A tool call OpenCode rejected fails the run, although OpenCode exits 0; agents stay inside their worktree | IC2 #501: on 2026-09-29 three runs read or wrote outside `--dir` (TEMP, a tool's install directory, a mutation copy). OpenCode auto-rejected each call and exited 0, so they looked like clean finishes and no fallback ran (#505). |
| L27 | One OpenCode model per role, then Claude: DeepSeek V4.1 Flash on Go implements, then Sonnet; GPT-6 Luna on the direct OpenAI route reviews, then Opus; effort `high`, never `max` (GLM is back, on watch: L35) | The owner's decisions of 2026-10-02, from IC2's runs. Chains of cheap models multiplied wasted attempts: in IC2 #554 a Luna failure stopped the chain before DeepSeek ran. GLM-5.3 and GLM-5.3 Flash ended long implementer runs early (a run of reading, then exit 0 with no commit), and GLM-5.3 Flash was the weakest reviewer elsewhere (it missed a must-fix). Here the first real run's GLM-5.3 Flash went 900 s without a step. Go's GPT-6 Luna is served by a third-party proxy (`novita-openai`) that returned `400 Bad Request {"model":"gpt-6-luna"}` mid-run in long agent loops (IC2 #551, #553); the direct OpenAI route did not fail. All these models have about 1M tokens of context, so context size is not the cause of early stops. `max` effort was slower, with no gain. |
| L28 | A review is never thrown away: only output with no review at all falls back (exit 3, Claude reviews). A readable review is posted normalised and acted on, its where-I-worked block and sign-off kept. A cut-off one, one with no readable verdict, one whose verdicts differ, or one with a finding after its closing verdict is posted whole under a note; only the last header is read, so an earlier draft never approves it, unlabelled, for the main session to read and decide (exit 4), never re-reviewed for pay. Closing keywords lose their `#` | The owner's decisions of 2026-10-02. A strict reader discarded paid reviews over decoration (bold headers, a `Verdict:` prefix, a sign-off) and paid for another, and a cut-off review still carries findings worth reading (IC2 #370). GitHub closes issues only from PR bodies and commits, never from comments. |
| L29 | OpenCode runs use the scripts' own data directory, and Go's login is made for it | IC2 #540: OpenCode's desktop app (2.x) migrated the shared `opencode.db`, and the 1.x CLI then failed with `no such column: project_id`. Go's `opencode console login` lives in the data directory's database, not in `auth.json` (IC2 #551), so each directory needs its own. |
| L30 | The reviewer runs `git` in its working directory, the worktree the script started it in, and never types the worktree's path | 2026-10-02, the first real `review.mjs` run (harness_imperial#15): Luna's first command was `git -C "<worktree>" … && git -C "<worktree>" …`, and in the second she wrote `82982c00f-8def` for `82982c00-8def` in a 90-character path. OpenCode rejected it as outside the worktree and ended the run after 17 s. The agent file had asked for `git -C` on every command, retyping the path each time; the tree proof (L8) does the job that rule was for. |
| L31 | Shell commands run from the worktree root with paths relative to it: no `cd`, no `..` | 2026-10-02 (#14): a read-only GLM-5.3 review chained `cd evidence/x && …; cd ../y && …`. OpenCode checks a command's paths before running it, against `--dir` and not the `cd` before them, so it resolved `../y` outside the worktree, auto-rejected the call as `external_directory`, and the run was discarded after about 25 minutes without a review, although nothing had left the directory. DeepSeek V4 Pro ran the same brief without a rejection, always giving paths from the root. |
| L32 | A review accounts for every Done-when line, one `DW<k>` line each (the command and its result, or why it was not run); an approve with one missing or not run is posted but not applied | 2026-10-02 (#19), game-archaeologist PR 2: `luna` approved with no findings, but showed no evidence for Done-when 3 (an ADR-by-ADR comparison). The main session did not merge on that; a supplementary review of Done-when 3 alone found two real defects (an ADR said "four new repos" and listed three; another dropped a clause its source states). The rule said "re-run every Done-when line", but nothing made the reviewer account for each, and an approval that skipped one looked like one that ran them all. |
| L33 | The brief names the PR's head as it is after the last push, taken from the local branch; `review.mjs` refuses a brief that names another commit, before anything runs | 2026-10-02 (#23): after pushing a fix to PR 21, the main session read the head with `gh pr view --json headRefOid` straight away; GitHub had not updated, so the brief named the old commit. The reviewer's tree proof stopped on the mismatch after a billed run, and the script posted that as a `rework` on the PR. 2026-10-03 (#32), malpaco PR 4: the check read the pasted task file too, and refused a brief whose task cited its source "at `<sha>`"; now only the lines before the task file's title (`# T<nn>`) are read. |
| L34 | The reviewer's agent and OpenCode config come from the main session's checkout, never from the PR under review | #10, after ic2-conquest's reviewer: OpenCode reads a project's `.opencode/` by default, so a PR that edits its own `reviewer.md` decides what its reviewer may do. Checked on OpenCode 1.18.34 on 2026-10-02: a worktree's `reviewer.md` with `git push *: allow` was the agent loaded; with `OPENCODE_CONFIG_DIR` at the main checkout and `OPENCODE_DISABLE_PROJECT_CONFIG=1` the main checkout's was. |
| L35 | Candidate models are registered in `harness.json` with a `watch` note, outside the chains: GPT-6 Sol, GPT-6.1 Sol, DeepSeek V4 Pro, and GLM-5.3 and GLM-5.3 Flash on Z.AI's plan. | L37 | A simpler repository takes the review profile: the main session plans and implements, related changes may share a PR, the PR body is the contract with `Critical: yes\|no`, and only reviewers run as agents: GLM-5.3 Flash, then Luna, then DeepSeek V4.1 Flash, then the user, never Claude. | L38 | After a heavy review, the next round's implementer moves one step up (light OpenCode → heavy OpenCode → Opus; Sonnet → Opus), never down.
